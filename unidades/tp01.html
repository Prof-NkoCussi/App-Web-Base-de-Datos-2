1. De los archivos a las bases de datos

Cómo evolucionaron los sistemas de bases de datos

Las bases de datos que se usan hoy son el resultado de más de sesenta años de cambios. Cada etapa buscó resolver los problemas de la anterior.

  1. Años 60

    Sistemas de archivos, como los CSV del TP3 de 5.º.

  2. Fines de los 60

    Modelos jerárquico, en árbol (IBM IMS, 1968), y de red (CODASYL).

  3. 1970

    E. F. Codd propone el modelo relacional: datos en tablas.

  4. Años 80

    SGBD relacionales en las empresas y SQL estándar (ANSI, 1986).

  5. Años 90

    Bases orientadas a objetos y bases en la web (MySQL, 1995).

  6. Desde 2009

    Bases NoSQL (no relacionales) y bases en la nube.

¿Qué problemas resolvió el cambio?

  • Archivos

    • Redundancia: el mismo dato se repite en varios archivos.
    • Inconsistencia: si se corrige en un archivo y no en otro, ya no coinciden.
    • Acceso difícil: cada consulta nueva necesita un programa nuevo.
    • Un usuario por vez: si dos lo modifican juntos, se pierden cambios.

  • Base de datos

    • Cada dato se guarda una sola vez.
    • Todos ven el mismo dato, siempre actualizado.
    • Se consulta con un lenguaje (SQL), sin programar cada búsqueda.
    • El SGBD permite varios usuarios a la vez.

Idea clave: Cada etapa cambió cómo se organizan los datos, para guardarlos sin repetir y consultarlos con facilidad.

2. ¿Qué es un SGBD / DBMS?

El software que administra la base de datos Repaso de 5.º

Un SGBD o DBMS es el programa que permite crear, guardar, consultar, modificar y proteger una base de datos.

  1. Usuario

    Personas que usan la información.

  2. SGBD / DBMS

    Software que administra la base de datos.

  3. Base de datos

    Datos organizados y almacenados.

Principales funciones del SGBD

  • Crear

    bases, tablas y relaciones.

  • Consultar

    buscar y mostrar información.

  • Modificar

    agregar, cambiar o eliminar datos.

  • Proteger

    control de acceso y copias de seguridad.

Funciones principales

  • organiza
  • controla
  • respalda
  • optimiza

Ejemplos de SGBD: MySQL, PostgreSQL, SQLite, SQL Server y Oracle.

Idea clave: La base de datos guarda la información; el SGBD la administra.

Un poco más sobre cada lámina

Lámina 1

¿Por qué ganó el modelo relacional?

En los modelos jerárquico y de red, el programa recorre los datos por un camino fijo; si cambia la forma de guardarlos, hay que reescribirlo.

El modelo relacional trajo dos ventajas: la independencia de los datos (el programa pide qué datos quiere, no cómo llegar a ellos) y un lenguaje común, SQL.

Ejemplo en la escuela

  • Jerárquico: para listar los alumnos con promedio mayor a 8, el programa recorre cada curso, alumno y nota.
  • Relacional: una consulta dice qué se quiere; el SGBD decide cómo buscarlo.
  • Si se agrega la columna email a ALUMNOS, la consulta sigue funcionando.

Lámina 2 · Ampliación

Los componentes del sistema

Según C. J. Date, un sistema de base de datos tiene cuatro componentes:

  • Datos: integrados y compartidos.
  • Hardware: los discos y la computadora que los procesa.
  • Software: el SGBD, intermediario entre usuarios y datos.
  • Usuarios: programadores, usuarios finales y el administrador de la base (DBA).

Ejemplo: el sistema de notas de la escuela

  • Datos: alumnos, materias y notas.
  • Hardware: el servidor de la escuela.
  • Software: el SGBD, por ejemplo, MySQL.
  • Usuarios: quien lo programó; docentes y alumnos, que lo usan; y el DBA, que da permisos y hace copias.

Lámina 3

Los nombres del modelo relacional

En la teoría, las partes de una tabla tienen nombres propios, los que usó Codd en 1970.

El dominio es el conjunto de valores posibles de un atributo: para edad, los enteros positivos.

La tienda de 5.º, con estos conceptos

La base de datos de la tienda del integrador de 5.º se puede describir con el esquema de la lámina 2: los usuarios trabajan con el SGBD, y el SGBD con la base de datos.

La tienda, parte por parte

  • SGBD: MariaDB, el que trae XAMPP (se maneja desde phpMyAdmin).
  • Usuarios: quien lo programó, los vendedores y dueños que lo usan, y el DBA.
  • Tablas: CLIENTES, PRODUCTOS, VENTAS y DETALLE_VENTA.
  • Relaciones: cada venta, con su cliente; cada detalle, con su venta y su producto.
