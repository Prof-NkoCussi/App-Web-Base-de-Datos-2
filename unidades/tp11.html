35. COUNT, SUM, AVG, MIN y MAX

Funciones para resumir y analizar datos

Las funciones de agregación en SQL permiten contar registros, obtener totales, calcular promedios y encontrar los valores mínimo y máximo de una columna.

¿Qué hace cada una?

  • COUNT

    Cuenta el número de registros que cumplen una condición.

  • SUM

    Calcula la suma de los valores de una columna numérica.

  • AVG

    Calcula el promedio de los valores de una columna numérica.

  • MIN

    Encuentra el valor mínimo de una columna numérica.

  • MAX

    Encuentra el valor máximo de una columna numérica.

Ejemplos en SQL

  • COUNT

    1. SELECT COUNT(*)
    2. FROM productos;

  • SUM

    1. SELECT SUM(precio)
    2. FROM productos;

  • AVG

    1. SELECT AVG(precio)
    2. FROM productos;

  • MIN

    1. SELECT MIN(precio)
    2. FROM productos;

  • MAX

    1. SELECT MAX(precio)
    2. FROM productos;

¿Para qué sirven?

  • Conteo de registros

    Útil para saber cuántos elementos tiene una tabla.

  • Totales

    Permite obtener la suma de valores (como ventas o precios).

  • Promedios

    Ayuda a conocer el valor medio de un conjunto de datos.

  • Análisis rápido

    Permite encontrar valores extremos (mínimos y máximos) para entender mejor los datos.

Idea clave: Las funciones de agregación resumen la información de una tabla sin mostrar cada registro de forma individual.

36. GROUP BY y HAVING

Agrupar registros y filtrar grupos

La cláusula GROUP BY permite agrupar registros que comparten un mismo valor en una columna. La cláusula HAVING se usa para filtrar los grupos después de aplicar funciones de agregación.

¿Qué hace cada uno?

  • GROUP BY

    Agrupa los registros que comparten el mismo valor en una o más columnas. Se usa junto con funciones de agregación.

  • HAVING

    Filtra los grupos resultantes después de aplicar funciones de agregación. Se usa para establecer condiciones sobre los grupos.

Ejemplo en SQL

  • Contar productos por categoría

    1. SELECT categoria, COUNT(*) AS cantidad
    2. FROM productos
    3. GROUP BY categoria;

  • Solo categorías con más de un producto

    1. SELECT categoria, COUNT(*) AS cantidad
    2. FROM productos
    3. GROUP BY categoria
    4. HAVING COUNT(*) > 1;

Puntos importantes

  • Agrupa por columna

    Usa GROUP BY con una o más columnas para formar grupos.

  • Usa funciones agregadas

    Como COUNT(), SUM(), AVG(), MIN() o MAX().

  • HAVING filtra grupos

    Se usa después de GROUP BY para establecer condiciones sobre los grupos.

  • Diferencia entre WHERE y HAVING

    WHERE filtra registros antes de agrupar. HAVING filtra grupos después de agrupar.

Idea clave: GROUP BY organiza los registros en grupos y HAVING decide qué resultados agrupados se mantienen.

37. JOIN: INNER JOIN y LEFT JOIN

Relacionar tablas para obtener información

JOIN se usa para combinar datos de dos o más tablas relacionadas. INNER JOIN devuelve solo las coincidencias. LEFT JOIN devuelve todos los registros de la tabla izquierda y las coincidencias de la derecha.

¿Qué hace cada uno?

  • INNER JOIN

    Devuelve solo los registros con coincidencia en ambas tablas.

  • LEFT JOIN

    Devuelve todos los registros de la tabla izquierda, aunque no tengan coincidencia en la derecha.

Ejemplo en SQL

  • INNER JOIN

    1. SELECT clientes.nombre, ventas.fecha
    2. FROM clientes
    3. INNER JOIN ventas
    4. ON clientes.id_cliente = ventas.id_cliente;

  • LEFT JOIN

    1. SELECT clientes.nombre, ventas.fecha
    2. FROM clientes
    3. LEFT JOIN ventas
    4. ON clientes.id_cliente = ventas.id_cliente;

    JOIN se usa para combinar datos de dos o más tablas relacionadas.

  • Usa ON

    La cláusula ON indica la condición que relaciona las tablas.

  • INNER filtra coincidencias

    Devuelve solo los registros que coinciden en ambas tablas.

  • LEFT conserva la tabla izquierda

    Devuelve todos los registros de la tabla izquierda, aunque no tengan coincidencia en la derecha.

Idea clave: INNER JOIN muestra solo coincidencias. LEFT JOIN mantiene todos los registros de la tabla izquierda y agrega las coincidencias cuando existen.

Lámina 35

COUNT, AVG y los vacíos

COUNT(*) cuenta filas. COUNT(columna) cuenta solo las filas que tienen un valor en esa columna: los vacíos (NULL) no se cuentan. AVG también ignora los NULL: divide la suma por la cantidad de valores, no de filas.

Con la tabla NOTAS

  • Carla no rindió: COUNT(*) da 4 y COUNT(nota), 3.
  • AVG(nota) da 8.3333: 25 ÷ 3. Si Carla contara como 0, sería 25 ÷ 4.
  • ROUND(AVG(nota), 2) redondea a 2 decimales: 8.33.

Lámina 36

El orden completo de una consulta

Con GROUP BY y HAVING, el orden en que el gestor lee una consulta (TP8, lámina 26) suma dos pasos:

  1. FROM
  2. WHERE
  3. GROUP BY
  4. HAVING
  5. SELECT
  6. ORDER BY

WHERE elige filas antes de armar los grupos, y HAVING elige grupos después. Por eso WHERE no acepta COUNT(*): cuando filtra, los grupos todavía no existen.

Las columnas del SELECT

Con GROUP BY, en el SELECT van solo las columnas del GROUP BY o funciones de agregación. Con GROUP BY categoria, pedir también el nombre no tiene sentido: Informática tiene tres productos y el gestor no sabe cuál mostrar. Algunos gestores dan error; MariaDB, como viene en XAMPP, muestra uno cualquiera.

Lámina 37

Alias de tabla y tres tablas

Un alias de tabla es un nombre corto: con FROM clientes c JOIN ventas v se escribe c.nombre y v.fecha. JOIN solo es INNER JOIN.

Con dos JOIN se combinan tres tablas: qué productos lleva cada venta (8 filas).

  1. SELECT v.fecha, p.nombre, d.cantidad
  2. FROM ventas v
  3. JOIN detalle_venta d
  4. ON v.id_venta = d.id_venta
  5. JOIN productos p
  6. ON d.id_producto = p.id_producto;

RIGHT JOIN y la reunión

RIGHT JOIN es el LEFT JOIN al revés: conserva toda la tabla derecha. INNER JOIN es la reunión del TP6 (lámina 19): CLIENTES VENTAS.

Todo junto

Total gastado por cada cliente

  1. SELECT c.nombre, SUM(v.total) AS gastado
  2. FROM clientes c
  3. JOIN ventas v
  4. ON c.id_cliente = v.id_cliente
  5. GROUP BY c.nombre
  6. ORDER BY gastado DESC;
  1. FROM y JOIN: cada venta, con su cliente (4 filas: Ana dos veces, Carlos y Sofía).
  2. GROUP BY c.nombre: un grupo por cliente.
  3. SELECT: el nombre y la suma de cada grupo (Ana 89000, Carlos 192000, Sofía 44500).
  4. ORDER BY gastado DESC: Carlos, Ana y Sofía. Puede usar el alias porque se lee después del SELECT.
