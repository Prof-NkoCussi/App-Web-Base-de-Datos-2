38. Subconsultas + introducción a CTE (WITH)

Consultas dentro de consultas y resultados temporales

Una subconsulta es una consulta dentro de otra consulta. Una CTE (Common Table Expression), escrita con WITH, crea un resultado temporal con nombre para usarlo en una consulta principal.

¿Qué es una subconsulta?

  • Se usa dentro de otra consulta.

  • Ayuda a filtrar o comparar resultados.

  • Puede ir en SELECT, FROM o WHERE.

Subconsulta: ejemplo

  1. SELECT nombre, precio
  2. FROM productos
  3. WHERE precio > (
  4. SELECT AVG(precio)
  5. FROM productos
  6. );

Este resultado muestra productos con precio mayor al promedio.

¿Qué es una CTE?

  • Se escribe con WITH.

  • Da nombre a un resultado temporal.

  • Mejora la legibilidad.

CTE: ejemplo

  1. WITH productos_caros AS (
  2. SELECT nombre, precio
  3. FROM productos
  4. WHERE precio > 10000
  5. )
  6. SELECT *
  7. FROM productos_caros;

Primero crea un conjunto temporal y luego lo consulta.

Comparación rápida

  • Subconsulta

    Va dentro de otra consulta.

  • CTE

    Crea un bloque temporal con nombre.

Ejemplo de tabla

PRODUCTOS
id_productonombreprecio
1Teclado8000
2Mouse2500
3Monitor12000
4Notebook45000

Puntos importantes

  • Filtrar por promedios

    Permite comparar con valores agregados.

  • Reutilizar resultados

    Las CTE permiten usar el mismo resultado varias veces.

  • Mejorar la claridad

    WITH hace las consultas más fáciles de leer y mantener.

  • Pensar paso a paso

    Permite dividir problemas complejos en partes más simples.

Idea clave: Las subconsultas y las CTE permiten resolver consultas más complejas. WITH suele hacer el SQL más claro y ordenado.

39. Scripts .sql

Un archivo con instrucciones que se ejecutan en orden

Un script es un archivo de texto con instrucciones SQL, una detrás de otra, que el gestor ejecuta en orden, de la primera a la última. escuela.sql y tienda.sql, que se importaron en los TPs anteriores, son scripts.

Comentarios

  • -- …

    De una línea: desde -- hasta el final del renglón. Después de los guiones va un espacio.

  • /* … */

    De varias líneas: todo lo que queda entre /* y */.

El gestor no los ejecuta: son notas para quien lee el script.

Cómo se ejecuta

  • En phpMyAdmin: pestaña Importar, elegí el archivo y hacé clic en Importar.

  • Desde la consola (botón Shell del panel de XAMPP): mysql -u root < tienda.sql, o entrá con mysql -u root y escribí SOURCE tienda.sql;

Si el archivo está en otra carpeta, se escribe su ruta; en SOURCE, con barras /: C:/Users/…/tienda.sql.

¿Para qué sirve?

  • Crear una base desde cero

    Con sus tablas y sus claves, en un solo archivo.

  • Cargar datos de prueba

    Para practicar, como tienda.sql.

  • Repetir en otra computadora

    La misma base, en el laboratorio o en casa.

  • Hacer respaldos

    Una copia de la base, para recuperarla (TP13).

Buenas costumbres

  • Empezar con DROP TABLE IF EXISTS (las tablas con clave foránea, primero): así se puede ejecutar otra vez.
  • Crear primero las tablas referenciadas: socios necesita que deportes ya exista.
  • Comentar cada parte: qué hace y por qué, para quien lo lea después.

Idea clave: Un script guarda en un archivo las instrucciones SQL, en orden: se ejecutan todas juntas, las veces que haga falta y en cualquier computadora.

40. SQL embebido en PHP

Usar la base de datos desde un programa

Un programa escrito en un lenguaje imperativo, como PHP, puede tener adentro instrucciones SQL: las manda al gestor, recibe los resultados y los usa, por ejemplo, para armar una página web.

  1. Conectarse

    new mysqli con el servidor y la base

  2. Preparar la consulta

    prepare con un ? por cada dato

  3. Pasarle los datos

    bind_param le da a cada ? su dato

  4. Ejecutarla

    execute el gestor la resuelve

  5. Recorrer los resultados

    get_result y fetch_assoc

  6. Mostrarlos

    echo cada fila, en la página

Ejemplo: clientes.php

Los clientes de una ciudad, en una lista. Usa la base tienda.

clientes.php · PHP
  1. <?php
  2. $conexion = new mysqli("localhost", "root", "", "tienda");
  3. $conexion->set_charset("utf8mb4");
  4. $ciudad = "Ushuaia";
  5. $sql = "SELECT nombre, edad FROM clientes WHERE ciudad = ?";
  6. $consulta = $conexion->prepare($sql);
  7. $consulta->bind_param("s", $ciudad);
  8. $consulta->execute();
  9. $resultado = $consulta->get_result();
  10. echo "<h1>Clientes de $ciudad</h1><ul>";
  11. while ($fila = $resultado->fetch_assoc()) {
  12. echo "<li>" . $fila["nombre"] . ", ";
  13. echo $fila["edad"] . " años</li>";
  14. }
  15. echo "</ul>";
  16. $conexion->close();

Cómo se prueba

  1. Guardá el archivo en C:\xampp\htdocs\bd2\.
  2. En el panel de XAMPP, iniciá Apache y MySQL.
  3. En el navegador, entrá a http://localhost/bd2/clientes.php.

Las funciones viejas mysql_connect() y mysql_query() ya no existen desde PHP 7: si aparecen en un apunte o un video, es material viejo.

Los datos del usuario, siempre con ?

Lo que escribe el usuario en un formulario nunca se pega directo en el SQL: va con ? y bind_param, en una consulta preparada. Así el gestor lo toma como un dato y no como parte de la instrucción. Más sobre esto en el Integrador final.

El usuario root

Sin contraseña, root es solo para el laboratorio. En el TP13 se crean usuarios con permisos.

Idea clave: Con SQL embebido, un programa se conecta a la base, le manda consultas preparadas y usa sus resultados, por ejemplo, para armar una página.

41. Un lenguaje de consulta de objetos

Consultas sobre objetos en lugar de tablas

En una base orientada a objetos (TP3, lámina 8), los datos se guardan como objetos, con sus atributos y sus vínculos con otros objetos. Por eso se consulta por objetos, atributos y relaciones, no por tablas y columnas.

OQL, del estándar ODMG

OQL (Object Query Language) es el lenguaje de consulta del estándar ODMG, que en los años 90 propuso cómo debían funcionar las bases orientadas a objetos. Se parece a SQL, con select, from y where, pero para ir de un objeto a otro relacionado usa un punto.

En OQL

OQL
  1. select a.nombre
  2. from a in Alumnos
  3. where a.curso.nombre = "6.º A"
  • a in Alumnos: a recorre todos los objetos de la clase Alumno.
  • a.curso: el curso del alumno (su grupo, como 6.º A), que es otro objeto.
  • a.curso.nombre: el nombre de ese curso.

Lo mismo en SQL

SQL
  1. SELECT a.nombre
  2. FROM alumnos a
  3. JOIN cursos c ON a.id_curso = c.id_curso
  4. WHERE c.nombre = '6.º A';

Los alumnos y los cursos están en dos tablas: para llegar al curso de cada alumno, hay que unirlas con JOIN por la clave foránea id_curso (TP11).

SQL y OQL: qué se consulta, cómo se relacionan los datos y qué devuelve cada uno
AspectoSQLOQL
ConsultaTablas y columnasObjetos y atributos
Para relacionarJOIN, con la clave foráneaUn punto: a.curso
DevuelveFilasObjetos o valores

Hoy la idea sigue en los ORM (TP3): en Java, JPQL, y en C#, LINQ, consultan con objetos, y el ORM lo traduce a SQL.

Idea clave: OQL consulta objetos: va de un objeto a otro relacionado con un punto, donde SQL necesita un JOIN.

Lámina 38

IN y subconsultas en el SELECT

Con IN, la subconsulta devuelve una lista y la consulta principal se queda con lo que está en ella. Los clientes que compraron alguna vez:

  1. SELECT nombre FROM clientes
  2. WHERE id_cliente IN (
  3. SELECT id_cliente FROM ventas
  4. );

La subconsulta da 1, 2, 1 y 5: salen Ana, Carlos y Sofía. Con NOT IN, los que nunca compraron.

En el SELECT, una subconsulta que da un solo valor es una columna más: el promedio de los precios, 141063, en cada fila.

  1. SELECT nombre, precio,
  2. (SELECT ROUND(AVG(precio))
  3. FROM productos) AS promedio
  4. FROM productos;

¿Cuándo conviene una CTE?

  • Cuando el mismo resultado se usa más de una vez: se calcula una sola vez, con nombre.
  • Cuando la consulta se vuelve larga: cada CTE es un paso con nombre, y se lee de arriba abajo.

Lámina 39

El script como respaldo

Un script también sirve para guardar una copia de una base, y phpMyAdmin lo escribe solo: con Exportar, arma un .sql con el CREATE TABLE y los INSERT INTO de cada tabla, con todos sus datos.

  1. Elegí la base a la izquierda y entrá a la pestaña Exportar.
  2. Dejá el método Rápido y el formato SQL, y hacé clic en Exportar.
  3. Se descarga un archivo con el nombre de la base: tienda.sql.

Para recuperarla

El archivo no trae CREATE DATABASE: se crea una base vacía, se la elige a la izquierda y se importa el archivo. Queda como estaba cuando se exportó. Cuándo y cómo hacer los respaldos se ve en el TP13.

Lámina 40

Otra forma de conectarse: PDO

PDO (PHP Data Objects) es otra forma de usar la base desde PHP. La consulta preparada es la misma; cambian la conexión, la forma de pasar los datos y la de recorrer el resultado.

clientes.php · mysqli
  1. $conexion = new mysqli("localhost",
  2. "root", "", "tienda");
  3. $conexion->set_charset("utf8mb4");
  4. $consulta = $conexion->prepare($sql);
  5. $consulta->bind_param("s", $ciudad);
  6. $consulta->execute();
  7. $resultado = $consulta->get_result();
  8. while ($fila = $resultado->fetch_assoc())
clientes_pdo.php · PDO
  1. $conexion = new PDO(
  2. "mysql:host=localhost;dbname=tienda;charset=utf8mb4",
  3. "root", "");
  4. $consulta = $conexion->prepare($sql);
  5. $consulta->execute([$ciudad]);
  6. while ($fila = $consulta->fetch(PDO::FETCH_ASSOC))
  • mysqli sirve solo para MySQL y MariaDB. PDO sirve para varios gestores (MariaDB, PostgreSQL, SQLite…) con el mismo código: cambia solo el texto de la conexión.
  • Las dos permiten consultas preparadas con ?. En PDO, execute recibe los datos en una lista, sin bind_param ni get_result.
  • Si la conexión falla, las dos cortan el programa con un error; con try / catch se lo atrapa y se muestra un mensaje propio, como en clientes_pdo.php.

Todo junto

Un pedido, tres formas: los productos que nunca se vendieron

  • Subconsulta

    1. SELECT nombre
    2. FROM productos
    3. WHERE id_producto NOT IN (
    4. SELECT id_producto
    5. FROM detalle_venta
    6. );

  • CTE

    1. WITH vendidos AS (
    2. SELECT id_producto
    3. FROM detalle_venta
    4. )
    5. SELECT nombre
    6. FROM productos
    7. WHERE id_producto NOT IN (
    8. SELECT id_producto
    9. FROM vendidos
    10. );

  • Desde PHP

    1. $sql = "SELECT nombre FROM productos
    2. WHERE id_producto NOT IN (
    3. SELECT id_producto
    4. FROM detalle_venta)";
    5. $consulta = $conexion->prepare($sql);
    6. $consulta->execute();
    7. $resultado = $consulta->get_result();

Las tres dan lo mismo: Notebook, el único producto que no aparece en detalle_venta. PHP le manda al gestor el mismo SQL y recorre el resultado con el while de clientes.php; como no lleva datos del usuario, no hace falta ? ni bind_param.
