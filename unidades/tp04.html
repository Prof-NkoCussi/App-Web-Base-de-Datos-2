11. Restricciones: NOT NULL, UNIQUE, DEFAULT y CHECK

Reglas para validar y cuidar los datos

Las restricciones (constraints) son reglas que se aplican a los campos de una tabla para validar los datos que se guardan. Ayudan a evitar errores, mantener la consistencia de la información y asegurar que los datos sean correctos y confiables.

Principales restricciones

  • NOT NULL

    El campo no puede estar vacío. Siempre debe tener un valor.

  • UNIQUE

    Los valores no pueden repetirse. Cada registro debe tener un valor único en ese campo.

  • DEFAULT

    Si no se ingresa un valor, se asigna un valor predeterminado automáticamente.

  • CHECK

    Valida que el valor cumpla una condición especifica (por ejemplo, que sea mayor que cero).

Ejemplo en una tabla

PRODUCTOS
id_producto (PK)nombre (NOT NULL)precio (CHECK)categoria (DEFAULT)
1Laptop750.00Electrónica
2Mouse25.00Accesorios
3Teclado40.00Accesorios

Cada campo tiene una restricción que ayuda a mantener los datos válidos y organizados.

Ejemplo en SQL

SQL
  1. CREATE TABLE productos (
  2. id_producto INT PRIMARY KEY,
  3. nombre VARCHAR(100) NOT NULL,
  4. precio DECIMAL(10,2) CHECK (precio > 0),
  5. categoria VARCHAR(50) DEFAULT 'General'
  6. );

También puedes combinar varias restricciones en una misma tabla para tener datos más seguros y consistentes.

Ejemplo: un campo puede ser NOT NULL y UNIQUE al mismo tiempo.

Idea clave: Las restricciones ayudan a mantener el orden, la consistencia y la calidad de los datos en la base de datos.

12. Integridad referencial

Que las relaciones entre tablas tengan sentido

La integridad referencial garantiza que un valor de clave foránea corresponda a un valor de clave primaria existente en la tabla relacionada. Así evitamos registros que hagan referencia a datos que no existen.

Ejemplo: CLIENTES y VENTAS

Cada venta debe estar asociada a un cliente que exista.

CLIENTES
id_clientenombreemail
1Ana Lópezana@ejemplo.com
2Carlos Ruizcarlos@ejemplo.com
3Laura Díazlaura@ejemplo.com
VENTAS
id_ventaid_clientefechamonto
10112026-01-10250.00
10222026-01-12120.00
10332026-01-15300.00

  • Ejemplo incorrecto

    No se puede registrar una venta con un id_cliente que no exista en la tabla CLIENTES.

    Venta 104 con id_cliente 99
    id_ventaid_clientefechamonto
    104992026-01-20180.00

    Error: el cliente con id_cliente = 99 no existe en la tabla CLIENTES.

  • Ejemplo correcto

    La venta referencia un cliente que sí existe.

    Venta 104 con id_cliente 1
    id_ventaid_clientefechamonto
    10412026-01-20180.00

    Correcto: el cliente con id_cliente = 1 existe en la tabla CLIENTES.

Ejemplo en SQL

SQL
  1. CREATE TABLE ventas (
  2. id_venta INT PRIMARY KEY,
  3. id_cliente INT NOT NULL,
  4. fecha DATE,
  5. monto DECIMAL(10,2),
  6. FOREIGN KEY (id_cliente) REFERENCES clientes(id_cliente)
  7. );

¿Por qué importa?

  • Evita registros huérfanos

    No hay ventas sin un cliente válido.

  • Mantiene la consistencia

    Las relaciones entre tablas siempre tienen sentido.

  • Genera confianza en los datos

    La información es más confiable y de mejor calidad.

Idea clave: Una clave foránea solo puede tomar valores que existan en la clave primaria de la tabla relacionada.

13. Claves candidatas, alternativas y foráneas

Cómo se elige la clave de una tabla

Una clave candidata es el campo, o el grupo mínimo de campos, que identifica cada fila sin repetirse. Una tabla puede tener varias: de ellas se elige la clave primaria.

Ejemplo: la tabla ALUMNOS

ALUMNOS
id_alumnodniemailnombre
147123456ana@mail.comAna
246987654luis@mail.comLuis
347555111ana.p@mail.comAna

nombre no es candidata: hay dos alumnas que se llaman Ana. Los otros tres campos no se repiten nunca.

Claves candidatas

  • id_alumno
  • dni
  • email

Cada una identifica a un alumno sin repetirse.

se elige una

Clave primaria

  • id_alumno

La candidata elegida.

Claves alternativas

  • dni
  • email

Las demás. Se aseguran con UNIQUE y NOT NULL (lámina 11).

Otras claves

  • Clave foránea Un campo que toma valores de la clave primaria de otra tabla, como id_cliente en VENTAS (lámina 12).

  • Clave compuesta La que usa más de un campo, como id_alumno + id_curso en INSCRIPCIONES, la tabla intermedia del TP2: un alumno no se inscribe dos veces en el mismo curso.

Idea clave: De las claves candidatas se elige una como primaria; las demás quedan como alternativas, con UNIQUE y NOT NULL.

Lámina 11

Cuando se rompe una restricción

Si una fila no cumple una restricción, el gestor la rechaza: no la guarda y muestra un error con la regla que no se cumplió.

En MariaDB, el gestor de XAMPP, CHECK se aplica. MySQL lo ignoraba antes de la versión 8.0.16.

Ejemplo: la ficha de inscripción

FICHAS
dni (UNIQUE)nombre (NOT NULL)curso (DEFAULT)
47123456Ana1.º A

Ana se cargó sin curso: quedó en 1.º A, el valor por defecto. Otra ficha con el DNI 47123456 se rechaza:

Duplicate entry '47123456' for key 'dni' (valor repetido en dni).

Lámina 12

Al borrar o modificar un registro

La clave foránea dice, después de REFERENCES, qué pasa con las ventas si se borra su cliente (ON DELETE) o si cambia su id (ON UPDATE):

  • RESTRICT: no lo permite. Es la opción por defecto.
  • CASCADE: hace lo mismo en las ventas.
  • SET NULL: deja id_cliente vacío (NULL); el campo no puede ser NOT NULL.

Ejemplo: se borra el cliente 2

Qué pasa con la venta 102, del cliente 2, al borrar ese cliente con cada opción
OpciónLa venta 102
RESTRICTError: el cliente no se borra
CASCADESe borra también
SET NULLQueda con id_cliente NULL

Con ON UPDATE CASCADE, si el cliente 2 pasa a ser el 20, su venta también.

Lámina 13

¿Clave natural o artificial?

Una clave natural es un dato que ya existe, como el DNI; una artificial se crea para la tabla, como id_alumno.

  • Natural: tiene sentido fuera de la base y no suma un campo, pero puede faltar (un alumno extranjero sin DNI) o cargarse mal.
  • Artificial: es corta, nunca cambia y no depende de los datos; es la más usada.

Dos sentidos de “clave secundaria”

En el diseño curricular y en muchos libros, es la clave foránea, la que relaciona tablas. En otros, es un campo por el que se busca seguido, como el apellido. En este cuadernillo se usa el primer sentido.

Todo junto

La tabla ALUMNOS, completa

Línea 2: clave primaria. Línea 3: clave alternativa. Líneas 4 a 6: NOT NULL, CHECK y DEFAULT. Línea 8: clave foránea; CURSOS tiene que existir antes.

Ejemplo: CREATE TABLE alumnos

SQL
  1. CREATE TABLE alumnos (
  2. id_alumno INT PRIMARY KEY,
  3. dni INT NOT NULL UNIQUE,
  4. nombre VARCHAR(100) NOT NULL,
  5. edad INT CHECK (edad >= 12),
  6. turno VARCHAR(10) DEFAULT 'mañana',
  7. id_curso INT NOT NULL,
  8. FOREIGN KEY (id_curso) REFERENCES cursos(id_curso)
  9. );
