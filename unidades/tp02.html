4. Introducción al Diagrama Entidad-Relación

El plano visual de una base de datos

Un Diagrama Entidad-Relación (DER) es una forma gráfica de representar las entidades, sus atributos y las relaciones entre ellas antes de crear la base de datos.

  • ENTIDAD

    Representa un objeto o concepto del mundo real sobre el que se almacenan datos.

    Ejemplo: ALUMNO

  • ATRIBUTO

    Representa una característica o dato de una entidad.

    Ejemplo: nombre, fecha_nacimiento

  • RELACIÓN

    Representa la asociación entre dos o más entidades.

    Ejemplo: se_inscribe en, imparte

Ejemplo de Diagrama Entidad-Relación

¿Para qué sirve?

  • Planificar la estructura

    Ayuda a organizar los datos antes de implementar la base de datos.

  • Evitar duplicación

    Permite identificar datos repetidos y mejorar el diseño.

  • Comunicar el diseño

    Es un lenguaje visual fácil de entender para todo el equipo.

  • Detectar relaciones

    Facilita encontrar cómo se conectan los datos entre entidades.

Idea clave: Un DER funciona como un plano o esquema de la base de datos antes de escribir el código SQL.

5. Cómo interpretar un DER

Leer entidades, atributos y relaciones

Para leer un Diagrama Entidad-Relación (DER) debes identificar primero las entidades, luego sus atributos, después las claves y finalmente las relaciones y su cardinalidad.

Ejemplo de DER

Pasos para interpretar un DER

  1. 1Identificar entidades

    Busca los rectángulos del diagrama. Cada uno representa una entidad (por ejemplo: CLIENTE, PEDIDO, PRODUCTO).

  2. 2Leer atributos

    Dentro de cada entidad aparecen sus atributos (campos) con sus nombres y tipos de información (por ejemplo: nombre, fecha, precio).

  3. 3Reconocer claves

    Identifica la clave primaria (PK) de cada entidad y las claves foráneas (FK) que relacionan entidades (por ejemplo: id_cliente en PEDIDO).

  4. 4Observar cardinalidad

    Revisa los símbolos y números de cardinalidad (1:1, 1:N, N:M) para entender cuántos registros de una entidad se relacionan con otra.

Leyenda

  • PK

    Clave Primaria (Primary Key) Identifica de forma única cada registro de una entidad.

  • FK

    Clave Foránea (Foreign Key) Referencia la clave primaria de otra entidad.

Idea clave: Un DER muestra la estructura de los datos (entidades, atributos y relaciones), no los valores reales de los datos.

6. Del DER a las tablas

Cómo se pasa el diagrama a la base de datos

Para construir la base de datos, cada parte del DER se convierte en una tabla, una columna o una clave.

  1. Entidad

    Cada entidad, una tabla.

  2. Atributo

    Cada atributo, una columna.

  3. Identificador

    El identificador, la clave primaria (PK).

  4. Relación 1:N

    La clave foránea (FK) va en la tabla del lado N.

  5. Relación N:M

    Una tabla intermedia con las dos claves foráneas.

Ejemplo: el DER de la lámina 4, en tablas

ALUMNO y CURSO son entidades: cada una es una tabla (por costumbre, con el nombre en plural). INSCRIPCIÓN es una relación N:M: se convierte en una tabla intermedia, con una clave foránea hacia cada entidad.

Lámina 4

La notación de Chen

Peter Chen propuso el modelo entidad-relación en 1976. Los símbolos de la lámina 4 son los de su notación.

El atributo identificador, el que distingue a cada ejemplar, va subrayado. Y cada relación se nombra con un verbo: “un alumno se inscribe en un curso”.

Ejemplo: una biblioteca

Se lee: un socio pide prestados muchos libros, y un libro lo piden prestado muchos socios.

Lámina 5

La notación pata de gallo

Es la de la lámina 5. La cantidad se dibuja en cada punta de la línea, junto a la entidad a la que se refiere:

  • Uno: una raya.
  • Muchos: la pata de gallo.
  • Opcional: un círculo; puede haber cero.

Lámina 6

¿Por qué una tabla intermedia?

Una clave foránea guarda un solo valor por fila. Si id_curso fuera una columna de ALUMNOS, cada alumno podría estar en un solo curso.

La tabla intermedia guarda una fila por cada par alumno–curso. Y puede tener atributos propios: datos que no son del alumno ni del curso, sino de la inscripción.

Ejemplo: INSCRIPCIONES, con fecha y nota

El 6 no es la nota de Ana ni la de Historia: es la nota de Ana en Historia.

Todo junto

De un enunciado a un DER

En el texto se marcan tres tipos de palabras:

  • Sustantivos: candidatos a entidades.
  • Verbos: candidatos a relaciones.
  • Características de cada cosa: atributos.

Ejemplo: un club deportivo

En un club, cada socio tiene número, nombre y teléfono, y se anota en actividades (nombre, día y cuota). Cada actividad la da un profesor, que puede dar varias.

  • Entidades: SOCIO, ACTIVIDAD y PROFESOR. “Club” no: es todo el sistema.
  • Relaciones: SOCIO se anota en ACTIVIDAD (N:M); PROFESOR da ACTIVIDAD (1:N).
  • Atributos: número, nombre, teléfono, día y cuota.
