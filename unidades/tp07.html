23. CREATE DATABASE y CREATE TABLE

Crear una base de datos y sus tablas Repaso de 5.º

Con CREATE DATABASE se crea una base de datos nueva. Con CREATE TABLE se crean las tablas donde se almacenarán los registros.

Paso 1: CREATE DATABASE

SQL
  1. CREATE DATABASE tienda;

Crea una base llamada tienda.

Paso 2: CREATE TABLE

SQL
  1. CREATE TABLE clientes (
  2. id_cliente INT PRIMARY KEY,
  3. nombre VARCHAR(80),
  4. email VARCHAR(120),
  5. ciudad VARCHAR(60)
  6. );

¿Qué define una tabla?

  • Nombre de la tabla

    Identifica la entidad que almacenará los registros.

  • Columnas

    Son los campos donde se guardará la información.

  • Tipos de datos

    Indican qué tipo de información puede tener cada columna (INT, VARCHAR, etc.).

  • Restricciones

    Establecen reglas para los datos (PRIMARY KEY, NOT NULL, UNIQUE, etc.).

Resultado

Tabla: CLIENTES
id_clientenombreemailciudad
(todavía sin registros)

Después de ejecutar los comandos, la base de datos tienda tendrá una tabla llamada clientes con estas columnas.

Idea clave: Primero se crea la base de datos; después se crean las tablas que van a organizar la información.

24. ALTER y DROP

Cambiar o borrar lo que ya se creó

Con ALTER TABLE se cambian las columnas de una tabla que ya existe, sin perder sus registros. Con DROP se borra una tabla o una base entera.

ALTER TABLE: cambiar una tabla

Los ejemplos usan la tabla clientes de la lámina 23.

  • ADD Agregar una columna

    1. ALTER TABLE clientes
    2. ADD telefono VARCHAR(20);

  • MODIFY Cambiar el tipo o el largo

    1. ALTER TABLE clientes
    2. MODIFY nombre VARCHAR(100);

  • CHANGE Cambiarle el nombre

    1. ALTER TABLE clientes
    2. CHANGE ciudad localidad VARCHAR(60);

  • DROP COLUMN Borrar una columna

    1. ALTER TABLE clientes
    2. DROP COLUMN telefono;

  • ADD FOREIGN KEY Agregar una clave foránea

    1. ALTER TABLE ventas
    2. ADD FOREIGN KEY (id_cliente) REFERENCES clientes(id_cliente);

    Desde ahora, cada venta tiene que ser de un cliente que exista en clientes.

CHANGE lleva el nombre viejo, el nuevo y el tipo. En MODIFY y CHANGE va la columna completa: lo que no se escribe, como un NOT NULL, se pierde.

DROP: borrar una tabla o una base

    1. DROP TABLE clientes;

    Borra la tabla y sus datos.

    1. DROP DATABASE tienda;

    Borra la base y sus tablas.

    1. DROP TABLE IF EXISTS clientes;

    Si no existe, no da error.

Antes de usar DROP

DROP borra la tabla con todos sus datos y no se puede deshacer.

Antes, conviene hacer un respaldo de la base (TP13).

Idea clave: ALTER TABLE cambia la estructura de una tabla que ya existe; DROP la borra entera, con todos sus datos.

25. INSERT INTO – cargar información

Agregar registros a una tabla Repaso de 5.º

INSERT INTO se usa para incorporar nuevos registros a una tabla. Permite indicar en qué columnas vamos a guardar cada valor.

Sintaxis básica

SQL
  1. INSERT INTO clientes
  2. (id_cliente, nombre, email, ciudad)
  3. VALUES (1, 'Ana', 'ana@mail.com', 'Ushuaia');

Ejemplo en una tabla

CLIENTES
id_clientenombreemailciudad
1Anaana@mail.comUshuaia
2Carloscarlos@mail.comTolhuin
3Lauralaura@mail.comRío Grande
4Pedropedro@mail.comBuenos Aires

Insertar varios registros

SQL
  1. INSERT INTO productos (id_producto, nombre, precio)
  2. VALUES (101, 'Teclado', 40000),
  3. (102, 'Mouse', 25000);

Puntos importantes

  • Respetar el orden

    Los valores deben ir en el mismo orden que las columnas indicadas.

  • Usar tipos correctos

    Cada valor debe ser del tipo de dato que acepta la columna (texto, número, fecha, etc.).

  • Completar campos obligatorios

    Debes incluir valores para las columnas que no admiten valores NULL.

  • Evitar duplicar la clave primaria

    No puedes insertar un registro con una clave primaria que ya exista en la tabla.

Idea clave: Cada vez que usamos INSERT INTO, agregamos datos nuevos a una tabla.

Lámina 25

Al cargar los datos

  • AUTO_INCREMENT: el gestor completa solo el id (1, 2, 3…); en el INSERT, esa columna no se nombra.
  • DEFAULT o NULL: la columna que no se nombra toma su DEFAULT; si no tiene, queda en NULL.
  • Orden de carga: primero la tabla referenciada; después, la que tiene la clave foránea. La venta de un cliente que no existe se rechaza.
  1. CREATE TABLE productos (
  2. id_producto INT AUTO_INCREMENT,
  3. nombre VARCHAR(80) NOT NULL,
  4. precio DECIMAL(10,2),
  5. stock INT DEFAULT 0,
  6. PRIMARY KEY (id_producto)
  7. );
  8. INSERT INTO productos (nombre)
  9. VALUES ('Teclado');

Queda: id_producto 1 (AUTO_INCREMENT), precio NULL y stock 0 (DEFAULT).

La base del Integrador 1, con sus claves. USE elige la base donde se crean las tablas.

  2. USE tienda;
  3. CREATE TABLE clientes (
  4. id_cliente INT PRIMARY KEY,
  5. nombre VARCHAR(80),
  6. email VARCHAR(120),
  7. ciudad VARCHAR(60)
  8. );
  9. CREATE TABLE productos (
  10. id_producto INT PRIMARY KEY,
  11. nombre VARCHAR(80),
  12. precio DECIMAL(10,2),
  13. stock INT
  14. );
  15. CREATE TABLE ventas (
  16. id_venta INT PRIMARY KEY,
  17. id_cliente INT,
  18. fecha DATE,
  19. total DECIMAL(10,2),
  20. FOREIGN KEY (id_cliente)
  21. REFERENCES clientes(id_cliente)
  22. );
  23. CREATE TABLE detalle_venta (
  24. id_venta INT,
  25. id_producto INT,
  26. cantidad INT,
  27. subtotal DECIMAL(10,2),
  28. PRIMARY KEY (id_venta, id_producto),
  29. FOREIGN KEY (id_venta)
  30. REFERENCES ventas(id_venta),
  31. FOREIGN KEY (id_producto)
  32. REFERENCES productos(id_producto)
  33. );
